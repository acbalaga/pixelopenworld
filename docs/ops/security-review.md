# Security review (POW-M2-06)

Against `docs/tech/02-save-security.md`. Each threat has the control that answers it, the tests that prove the control, and the residual risk in plain words. Tests are named by file and title so they can be found by search. CI runs all of them (`npm run verify` and the Playwright suite).

This is a client-only scheme with no secret that stays secret. A programmer who studies the bundle can write their own tool. That is the bar the owner set, and it is stated, not hidden.

## Dependency review

- Runtime dependencies: none. `package.json` has only `devDependencies`, and the shipped client is built output.
- Lockfile: `package-lock.json` (version 3) pins 270 packages, every one with an integrity hash from `registry.npmjs.org` over https. `npm ci` is used in CI.
- `npm audit --audit-level=high` is clean (CI gate). `npm audit` at moderate reports 7 findings, all one chain: `minimatch` 7.0.0 to 11.0.0 (denial of service through glob pattern amplification) reached through `typescript-eslint` and its parser and utilities.
  - **Accepted exception.** These are lint-time development tools. None is in the shipped bundle (there is no runtime dependency), none runs on a player's device, and `minimatch` is fed only this repository's own file globs. Re-check when `typescript-eslint` publishes a release that moves off the affected range.

## Findings from this review

1. **Debug attributes on the canvas.** The page sets `data-saved-hash`, `data-loaded-hash` and similar on the canvas element so the end to end tests can read what was saved. They hold hashes, not state, so nothing useful is exposed. They are left in because the tests need them in the production build. Say if they should be stripped from deployed builds.
2. **Hardening gap closed.** CI did not run `check:seal` or `check:pwa`; both, plus `check:prod` and `check:deps`, now run in CI.
3. **No Help section existed.** System now has Help with the privacy note, as tech/02 requires.
